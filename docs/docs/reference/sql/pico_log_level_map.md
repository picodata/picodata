# PICO_LOG_LEVEL_MAP

Скалярная функция `pico_log_level_map` возвращает объект в формате [JSON],
сопоставляющий названия всех уровней журналирования с их числовыми значениями.
Чем больше число, тем подробнее отладочный журнал.
Состав объекта не зависит от текущего уровня журналирования.

Функцию можно вызывать в списке возвращаемых значений после `SELECT`,
в том числе без `FROM`: `SELECT pico_log_level_map();`. Непосредственные вызовы
в `WHERE`, `JOIN ... ON`, `GROUP BY` и `ORDER BY` не поддерживаются.

Функция доступна всем пользователям и не требует привилегий администратора.

![PICO_LOG_LEVEL_MAP](../../images/ebnf/pico_log_level_map.svg)

Функция вызывается без аргументов.

## Примеры {: #examples }

Получить все уровни журналирования:

```sql
SELECT pico_log_level_map();
```

Функция вернет объект со следующими значениями:

```json
{
  "fatal": 0,
  "system": 1,
  "error": 2,
  "crit": 3,
  "warn": 4,
  "info": 5,
  "verbose": 6,
  "debug": 7
}
```

Получить числовое значение текущего уровня, возвращаемого
[PICO_LOG_LEVEL](pico_log_level.md):

```sql
SELECT pico_log_level_map()[pico_log_level()];
```

Например, для уровня `'info'` результат будет равен `5`.

[JSON]: ../sql_types.md#json
