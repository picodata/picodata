# Использование векторных множеств

Векторное множество хранит именованные векторы и ищет среди них
ближайшие к заданному. Поддерживаются следующие команды:

- [`VADD`](supported_commands.md#vadd)
- [`VSIM`](supported_commands.md#vsim)
- [`VREM`](supported_commands.md#vrem)
- [`VEMB`](supported_commands.md#vemb)
- [`VCARD`](supported_commands.md#vcard)
- [`VDIM`](supported_commands.md#vdim)
- [`VISMEMBER`](supported_commands.md#vismember)
- [`VRANDMEMBER`](supported_commands.md#vrandmember)
- [`VRANGE`](supported_commands.md#vrange)
- [`VGETATTR`](supported_commands.md#vgetattr)
- [`VSETATTR`](supported_commands.md#vsetattr)
- [`VINFO`](supported_commands.md#vinfo)
- [`VLINKS`](supported_commands.md#vlinks)

Поиск `VSIM` использует приближённый HNSW-граф и косинусную метрику.
Опция `TRUTH` включает точный перебор всех векторов.

См. также:

- [Поддерживаемые команды](supported_commands.md)

## Добавление элементов и EF {: #adding_elements }

**EF** (Exploration Factor) — параметр, который определяет, сколько
потенциальных соседей проверяется при добавлении нового вектора в граф.

Пример добавления трёхмерного вектора:

```text
VADD vectors VALUES 3 0.1 0.2 0.3 element EF 300
```

Особенности:

- `EF` задаёт число кандидатов, которое граф рассматривает при
  добавлении конкретного элемента. Большее значение обычно улучшает
  связи графа и точность последующего поиска, но замедляет вставку. По
  умолчанию — `200`, допустимые значения — от `1` до `1000000`.
- `EF` относится только к одной вставке, а не ко всему ключу. Поэтому у
  разных `VADD` для одного множества могут быть разные значения `EF`.
  При обновлении существующего элемента используется `EF` новой вставки.

Режимы квантизации `M` и `REDUCE`, наоборот, являются параметрами всего
множества — их нужно повторять в каждом `VADD` с теми же значениями,
иначе команда вернёт ошибку.

## Квантизация {: #quantization }

Режим выбирается первым `VADD`:

- `Q8` — режим по умолчанию. Каждая координата после нормализации занимает один байт, что уменьшает потребление памяти ценой потери точности
- `NOQUANT` — отключает квантизацию и хранит координаты как числа с плавающей точкой. Требует больше памяти
- `BIN` — двоичная квантизация. Поддерживается для совместимости, но по замерам слишком сильно снижает точность поиска, поэтому не рекомендуется

Особенности:

- `VEMB` возвращает вектор после проекции, нормализации и квантизации, а для режимов `Q8` и `NOQUANT` умножает его координаты обратно на сохранённую норму
-  Для `BIN` координаты возвращаются без умножения на норму, поэтому ответ может отличаться от переданного в `VADD` вектора
-  При использовании `REDUCE` исходную размерность восстановить нельзя, как и в Redis

## Настройки плагина {: #plugin_configure }

| Параметр | Значение по умолчанию | Назначение |
|---|---:|---|
| `vectorset.search_threads` | `4` | Число потоков в пуле поиска `VSIM`. Допустимы только значения не меньше `1`. Если параметр не задан или равен `null`, пула нет: поиск выполняется в потоке транзакции, а остальные команды ждут его завершения, как в Redis на главном потоке. |
| `vectorset.initial_capacity` | `1024` | Начальная ёмкость графа каждого векторного множества. |

Для изменения параметров `vectorset.search_threads` и
`vectorset.initial_capacity` достаточно указать новые значения для них в файле
конфигурации плагина, например:

```yaml
vectorset:
  search_threads: 4
  initial_capacity: 1024
```

Также, изменить эти настройки можно через SQL:

```sql
ALTER PLUGIN radix 1.3.0 SET radix.vectorset.search_threads = '8';
```

!!! note "Примечание"
    Граф векторного множества первоначально
    формируется при [включении плагина Radix](install.md#plugin_enable) в
    кластере. Граф не хранится на диске и перестраивается с нуля на основе
    данных, хранящихся на инстансе, при каждом запуске инстанса. Во время
    построения графа кластер временно не принимает клиентские запросы.

## Отличия от Redis {: #difference_from_redis }

- Граф не сохраняется на диск. Векторы и атрибуты хранятся в спейсах Picodata, а граф заново строится при запуске узла. Из-за другого порядка построения приближённый `VSIM` после перезапуска может вернуть другой набор ближайших соседей. `VSIM ... TRUTH` остаётся точным.
- `VSIM ... FILTER` проверяет атрибуты во время обхода графа. Пока не исчерпан `FILTER-EF`, отбор точный. По умолчанию бюджет равен `COUNT × 100`; после его исчерпания ответ может содержать меньше `COUNT` элементов и отличаться от ответа Redis с тем же бюджетом.
- Вложенность JSON в атрибутах и выражениях `FILTER` ограничена 32 уровнями. Более глубокое значение считается отсутствующим полем. Это ограничение защищает процесс Picodata от переполнения стека.
- `VRANDMEMBER` выбирает элементы равномерно из хранилища, а не обходом графа, как Redis.
- Связи и порядок соседей в ответе `VLINKS` могут отличаться от Redis: реализации строят разные графы. Слои возвращаются сверху вниз, нулевой слой идёт последним.
- `VINFO max-level` не уменьшается после удаления элемента верхнего уровня.
- `CAS` в `VADD` принимается, но не меняет способ выполнения: вставка всегда выполняется в основном потоке хранилища. Результат команды, включая обновление существующего элемента, совпадает с выполнением без `CAS`.
