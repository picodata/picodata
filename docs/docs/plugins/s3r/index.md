# Общие сведения

S3R представляет собой плагин объектного хранилища для СУБД Picodata с интерфейсом,
совместимым с Amazon S3. Руководство описывает его устройство, установку,
настройку и эксплуатацию. Это же руководство поставляется вместе со сборкой
плагина.

!!! tip "Picodata Enterprise"
    Функциональность плагина доступна только в коммерческой версии Picodata.

## Что такое S3R {: #intro }

[Плагин](../../overview/glossary.md#plugin) работает внутри кластера
Picodata и превращает его в хранилище объектов: клиенты обращаются к нему по
протоколу S3 теми же средствами, что и к Amazon S3.

- Метаданные, то есть [бакеты](reference/glossary.md#bucket), ключи и атрибуты объектов, хранятся в таблицах
  Picodata. Внешние компоненты, например etcd, не нужны.
- Содержимое объектов хранится на локальных дисках [узлов](reference/glossary.md#node) и защищается
  репликацией либо [избыточным кодированием](reference/glossary.md#erasure_coding) Рида-Соломона.
- Малые объекты хранятся вместе с метаданными и читаются из оперативной
  памяти. Границу задаёт параметр `inline_max`, по умолчанию 4 КиБ.
- Кластер может занимать одну или несколько площадок. При нескольких
  [площадках](reference/glossary.md#site) каждая хранит свою копию объектов.

## Обозначения в примерах {: #example_cluster }

Команды и фрагменты конфигурации во всём руководстве относятся к одному
условному кластеру.

| Что | Значение в примерах |
|---|---|
| Узлы | `node1.example.net`, `node2.example.net`, `node3.example.net`; в [доменах отказа](reference/glossary.md#failure_domain) они объявлены как `host: node1`, `host: node2`, `host: node3` |
| Эндпоинт S3 на узле | `https://node1.example.net:8443`, сертификат выпущен собственным удостоверяющим центром (`/etc/s3r/ca.pem`). Значение параметра `listen` по умолчанию равно `127.0.0.1:8000` |
| Адрес S3 для клиентов | `https://s3.example.net`, балансировщик перед эндпоинтами узлов |
| Адрес [тенанта](reference/glossary.md#tenant) | `acme.s3.example.net` |
| Консоль и [API управления](reference/glossary.md#management_api) | `https://console.example.net/s3gateway/console/` и `https://console.example.net/s3gateway/api/`, обратный прокси перед HTTP-портом Picodata 6006 |
| Обмен фрагментами между узлами | порт 8700 |
| [Провайдер идентификации](reference/glossary.md#identity_provider) | `https://keycloak.example.net`, область `s3r` |
| Администратор | пользователь Picodata `ivanov` |
| Версия плагина в командах | `2.2.0` |
| Бакет | `documents` |

Адреса, порты и имена условны: подставляйте свои. Маршруты API управления в тексте записаны
без базового пути: `GET /v2/disks` означает запрос
`GET https://console.example.net/s3gateway/api/v2/disks`. Диагностические пути `/-/…`
обслуживает эндпоинт S3-узла.

Каждая версия плагина собирается под свою версию Picodata. Какая версия
Picodata нужна, указано в таблице
[Соответствие версий S3R и Picodata](install/requirements.md#picodata_s3r_versions).
