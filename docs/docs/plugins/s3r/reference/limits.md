# Ограничения

Перечень ограничений версии 2.2.0 плагина S3R: возможности, которые не поддерживаются, и параметры,
которые не входят в проверенные сценарии применения. Страница нужна тому, кто оценивает, подходит
ли хранилище для задачи, и тому, кто выясняет, почему операция не работает так, как в Amazon S3.

Ограничения сгруппированы по областям. В столбце «Что использовать» указан способ получить нужный
результат другими средствами либо раздел руководства, в котором описана соответствующая
функциональность.

Если в ограничении названо число и сказано «константа», оно задано в коде или формате хранения и
параметрами не изменяется.

## Интерфейс S3 {: #limits_s3 }

| Ограничение | Описание | Что использовать |
| --- | --- | --- |
| Удаление с многофакторным подтверждением (MFA Delete) | Не поддерживается. Поле `MFADelete` в настройке версионирования и заголовок `x-amz-mfa` защиты не обеспечивают. | Неизменяемость данных обеспечивается блокировкой объектов. |
| Шифрование на стороне сервера | Операции `PutBucketEncryption`, `GetBucketEncryption` и `DeleteBucketEncryption`, заголовки `x-amz-server-side-encryption` и схема SSE-C не поддерживаются. Данные на дисках не шифруются. | Данные на дисках шифруются средствами носителя или файловой системы. Шифрование трафика описано в разделе [Шифрование трафика](../admin/tls.md). |
| Загрузка формой из браузера (`POST Object`) | Подстановка `${filename}` не поддерживается. Поля формы `acl` и `tagging`, принятые в AWS, не учитываются: предопределённый список управления доступом и теги объекта задаются полями `x-amz-acl` и `x-amz-tagging`. Невыполненное условие политики формы возвращает ответ `400` вместо `403`. | Подпись, срок действия политики и условия `eq`, `starts-with` и `content-length-range` проверяются. |
| Уведомления о событиях | Не поддерживаются. | Изменения отслеживаются перечислением объектов либо запросом SQL к таблице `s3r_t<N>_object`. |
| Статический веб-сайт | Конфигурация сайта сохраняется, но сайт не обслуживается: индексный документ, страница ошибки и правила перенаправления не применяются. | |
| Журналирование обращений к [бакету](glossary.md#bucket) (`PutBucketLogging`) | Не поддерживается. | Запросы записываются в журнал [инстанса](glossary.md#instance). |
| Выборка внутри объекта (`SelectObjectContent`) | Не поддерживается. | |
| Каталожные бакеты S3 Express (`ListDirectoryBuckets`) | Не поддерживаются. | |
| Настройка репликации (`PutBucketReplication`) | Не поддерживается. | [Репликация между площадками](glossary.md#site_replication) определяется топологией кластера, см. [Репликация между площадками](../concepts/site_replication.md). |
| Скорость чтения при копировании между площадками и переносе между ярусами | Каждую полосу объекта S3R читает не дольше 30 секунд, иначе копия или перенос прерывается и повторяется позже. | При полосе 128 МиБ нужна скорость чтения не меньше 4,3 МиБ/с. |
| Восстановление архивных объектов (`RestoreObject`) | Не поддерживается. Объект в классе `GLACIER` или `DEEP_ARCHIVE` доступен для чтения сразу. | См. [Классы хранения S3 и ярусы](../concepts/storage_classes.md#storage_classes_and_tiers). |
| Перенос в класс с более частым доступом | Правила жизненного цикла переносят объекты только в классы с более редким доступом. | |
| Условия `IpAddress` и `NotIpAddress` | Не поддерживаются в политике бакета. Инструкция с таким условием трактуется в пользу отказа. | |
| Ключи условий `aws:*` и другие ключи вне списка | Не поддерживаются в политике бакета: `aws:username`, `aws:SourceIp`, `aws:CurrentTime`, `s3:VersionId`, `s3:delimiter`, `s3:max-keys` и любой ключ, кроме `s3:prefix`, `s3:ExistingObjectTag/<ключ>`, `s3:RequestObjectTag/<ключ>` и `s3:x-amz-<заголовок>`. Условие с таким ключом трактуется в пользу отказа, а `PutBucketPolicy` принимает его без ошибки. | См. [Политика бакета](../usage/access.md#bucket_policy). |
| Применение настроек бакета на других инстансах | Следующий запрос к инстансу, который не подтвердил применение изменения, ещё может быть обработан по прежним настройкам, см. [Применение настроек бакета](#limits_bucket_settings). | |
| Временные учётные данные (STS) и Bearer-токены | Не поддерживаются. Срок действия ключа доступа не задаётся. | Ключ действует, пока существуют запись о нём и пользователь, которому он выдан. |
| Интеграции | Отправка событий в Kafka, вызов функций, интеграция с системами биллинга, драйвер CSI, векторный поиск и RDMA не поддерживаются. | |

### Применение настроек бакета {: #limits_bucket_settings }

- Ответ на изменение политики, ACL, CORS, версионирования и других настроек бакета, кроме
  конфигурации веб-сайта, отправляется после того, как изменение применили все инстансы в состоянии
  `Online`.
- Инстансы опрашиваются одновременно, и ожидание ограничено 500 мс. Срок задан константой.
- Об инстансе, который не подтвердил применение, появляется запись в журнале. Следующий запрос к
  нему ещё может быть обработан по прежним настройкам.

## Дедупликация и сжатие {: #limits_dedup }

| Ограничение | Описание | Что использовать |
| --- | --- | --- |
| Объекты со [способом хранения](glossary.md#encoding) `inline` | Не дедуплицируются и не сжимаются. | Содержимое таких объектов хранится в строке метаданных. |
| Ранее записанные объекты | Включение сжатия не сжимает записанные объекты. Копия, записанная до того, как содержимое стало общим, сохраняет собственные данные до перезаписи, и процесс согласования её не объединяет. | |
| Выключение [дедупликации](glossary.md#deduplication) | Уже объединённое содержимое остаётся общим. | |
| Граница дедупликации | Дедупликация не выходит за пределы [яруса](glossary.md#storage_tier). | |
| Дедупликация без передачи содержимого | Проверка совпадения по контрольной сумме до передачи тела и `CopyObject` без копирования данных не поддерживаются. | |
| Выбор алгоритма сжатия | Не поддерживается. Применяется алгоритм zstd. | См. [Сжатие](../concepts/tenants.md#compression). |
| Сжатие в ярусе | Переключатель яруса не сжимает части [составной загрузки](glossary.md#multipart_upload), копии объектов и объекты, перенесённые в ярус правилом жизненного цикла. | Переключатели бакета и тенанта действуют и на части, и на копии. |

## Квоты {: #limits_quotas }

| Ограничение | Описание | Что использовать |
| --- | --- | --- |
| Точность [ограничения частоты](glossary.md#rate_limiting) и скорости | Суммарная частота может превышать заданную, см. [Точность ограничения частоты](#limits_rate_precision). | Доли инстанса показывает `GET /-/debug/quota`. См. [Квоты и ограничение скорости](../admin/quotas.md). |
| Учёт потребления | Таблица `s3r_quota_usage` не сверяется с хранимыми объектами. Если инстанс аварийно завершился между учётом объекта и его записью, объём и число объектов остаются учтёнными за объект, которого нет. | Процедуры ручной сверки нет. |
| Подсчёт имеющихся объектов при новой квоте | Пока фоновый подсчёт не завершён, записи под квотой не отклоняются, а после него потребление может отличаться от хранимого, см. [Подсчёт объектов под новой квотой](#limits_quota_seed). | Подсчёт не завершён, пока в строке `s3r_quota_usage` задан `seed_hlc`. |
| Потребление до первой записи под квотой | Нулевое потребление не означает, что данных нет, см. [Потребление до первой записи](#limits_quota_first_write). | Поле `bytes_used` запроса `/v2/capacity` и поля `storage_usage` и `objects_usage` настроек бакета в этом случае равны `null`, см. [Квоты и ограничение скорости](../admin/quotas.md). |

### Точность ограничения частоты {: #limits_rate_precision }

- Инстанс, у которого нет действующей доли общего предела, пропускает запросы без ограничения и
  запрашивает долю.
- Доля истекает через 4 с после потери связи с [узлом](glossary.md#node), который её выдал. Срок задан константой.
- Суммарная частота превышает заданную, пока координатор Picodata не признает этот узел
  отключённым.
- Локальное ограничение применяется, только пока дерево распределения долей не построено.

### Подсчёт объектов под новой квотой {: #limits_quota_seed }

Пока фоновый подсчёт объектов под новой квотой `bytes` или `objects` не завершён:

- записи под ней не отклоняются;
- `/v2/quotas` показывает потребление без ещё не подсчитанных объектов;
- если с начала подсчёта удалено больше, чем записано, потребление показывается равным 0.

После подсчёта потребление может отличаться от хранимого в пяти случаях:

1. Запись принята до того, как квота дошла до [репликасета](glossary.md#replicaset), который ведёт учёт, а сохранена после
   начала подсчёта.
2. Удалён объект, до которого подсчёт ещё не дошёл.
3. Во время подсчёта [виртуальный бакет vshard](glossary.md#vshard_bucket) перенесён на другой репликасет.
4. Часы инстанса, сохранившего объект, отстают от часов репликасета, который ведёт учёт.
5. Часы инстанса, сохранившего неучтённый объект до начала подсчёта, спешат относительно часов
   репликасета, который ведёт учёт.

### Потребление до первой записи {: #limits_quota_first_write }

Пока после установки квоты не выполнена первая запись, которую эта квота учитывает:

- поле `storage_usage` в ответах `/v2/quotas/tenant_quota` и `/v2/quotas/bucket_quota` равно 0;
- в ответе `/v2/quotas` равно 0 поле `usage` у квот `bytes` и `objects`.

Значение 0 здесь не означает, что данных нет. Первая запись запускает подсчёт уже хранимых
объектов.

## Хранение {: #limits_storage }

| Ограничение | Описание | Что использовать |
| --- | --- | --- |
| Тип носителя | Тип носителя автоматически не определяется, кэширование на твердотельных накопителях не выполняется. | Носители разделяются по ярусам свойством `tier=`, см. [Классы хранения S3 и ярусы](../concepts/storage_classes.md#storage_classes_and_tiers). |
| Перебалансировка фрагментов | Расширение кластера не переносит [фрагменты](glossary.md#chunk) между [группами размещения](glossary.md#placement_group). | Новые диски используются для новых групп. Перебалансировка метаданных средствами [vshard](../../../overview/glossary.md#vshard) выполняется. |
| Запись при `write_tolerance = 0` | Недоступность одного [участника группы](glossary.md#member) делает запись в группу невозможной. | См. [Кворум записи](../concepts/architecture.md#write_quorum). |
| Восстановление копии площадки | Копия объекта на [площадке](glossary.md#site) не восстанавливается по копиям других площадок. В [раскладке](glossary.md#layout) `instance` безвозвратный отказ узла оставляет объекты из его групп без копии на его площадке. | Такие объекты читаются с других площадок, см. [Пример: несколько площадок](../install/planning.md#many_places). |
| Фактор репликации больше числа площадок | Не поддерживается: Picodata не заполняет такие репликасеты, и кластер не проходит [начальное формирование](glossary.md#formation). | На нескольких площадках [фактор репликации](../../../overview/glossary.md#replication_factor) равен их числу. |
| Возврат групп на позиции | [Несимметричные](glossary.md#asymmetric_group) группы сами на свои позиции не возвращаются. | Действие «Восстановить размещение», см. [Восстановление размещения групп](../admin/disks.md#reform). |
| Изменение локального списка дисков | После первой регистрации изменение `S3R_DISKS` не действует. Инстанс один раз пишет в журнал предупреждение с обоими списками. | Диски меняют действиями [API управления](glossary.md#management_api), см. [Действия с дисками](../admin/disks.md). |
| Зависший накопитель при первом запуске | Если накопитель перестаёт отвечать во время разметки при первом запуске инстанса, разметка не завершается. Инстанс не регистрирует диски и не записывает причину, а начальное формирование ждёт его. Срок ожидания не ограничен. | Последняя запись журнала о таком диске: `formatting <путь> for this instance's first start`. Замените накопитель или уберите его из `S3R_DISKS` и перезапустите инстанс. |
| Досрочное завершение формирования | Не поддерживается: кластер не принимает запись, пока не пройдёт начальное формирование. | См. [Если установка не завершается](../install/troubleshooting.md#install_troubleshooting). |
| Ёмкость диска в группе | Одна группа размещения использует на диске не больше 65 536 крупных и 8 388 608 [малых блоков](glossary.md#block). Оба числа заданы форматом. | Остальную ёмкость диска занимают другие группы. Предел зависит от `stripe_size` и `k`, см. [Выбор ёмкости и размера экстента](../concepts/disks.md#capacity_choice). |

## Управление и эксплуатация {: #limits_operations }

| Ограничение | Описание | Что использовать |
| --- | --- | --- |
| Журнал действий пользователей S3 | Не ведётся. Выгрузка событий по протоколу syslog и в формате CEF не поддерживается. | Административные действия попадают в журнал аудита Picodata. |
| Набор ролей | Роли фиксированы: `s3r_superuser`, `s3r_observer`, `s3r_tenant_admin_<идентификатор>` и `s3r_user`. Конструктора ролей и роли аудитора нет. | См. [Роли](../admin/console_login.md#roles). |
| Учётные записи из LDAP и двухфакторная аутентификация | Средствами плагина не поддерживаются. | Обе возможности настраиваются у внешнего [провайдера идентификации](glossary.md#identity_provider), см. [Первый вход в консоль управления](../admin/console_login.md#accessing_console). |
| Статистика обращений по бакетам | В метриках не публикуется. | Метрики перечислены в разделе [Метрики](../admin/monitoring.md#metrics). |
| Конфигурация через API управления | API управления не изменяет конфигурацию плагина и состав кластера. | Конфигурация изменяется командой `ALTER PLUGIN`, состав кластера изменяется средствами Picodata. |
| Распределение чтений по репликам | При `read_preference = any` чтение, которое инстанс не может обслужить сам, Picodata направляет ближайшей реплике репликасета. Без настроенных зон это одна и та же реплика для всех инстансов, и она может оказаться [мастером](glossary.md#master). | Чтение обслуживает сам инстанс, получивший запрос, если у него есть копия нужных метаданных. Запросы клиентов распределяются по всем инстансам кластера. |
| Резервное копирование | Процедура согласованного резервного копирования и восстановления кластера не определена. | Снимок таблиц Picodata не содержит данных объектов, а копия директорий дисков не содержит метаданных. |
| Обновление между версиями | Процедуры обновления и отката кластера с данными нет. Выпуски меняют схему таблиц в существующих миграциях. | Кластер разворачивается заново, см. [Обновление и откат](../install/upgrade_remove.md#upgrade_and_rollback). |

## Проверенные границы {: #limits_tested }

| Ограничение | Описание | Что использовать |
| --- | --- | --- |
| Объём хранилища свыше 64 ПБ | Установки такого объёма не испытывались. | Программного ограничения нет. |
| [Схемы избыточности](glossary.md#erasure_shape) с числом фрагментов больше двадцати | Не проверялись и целевым сценарием не являются. | Например, схема 61+3. |
